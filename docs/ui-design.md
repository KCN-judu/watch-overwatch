# 界面设计

依据：`yata/.claude/skills/software-ui-ux-design`。设计顺序为 领域模型 → 用户目标与任务 → 信息架构 → 交互 → 层级与布局 → 视觉语言 → 实现。本文按此顺序，视觉部分排在最后。技术栈为 Flutter（Windows 桌面），数据来自本机 `watchd` 的 IR 接口。

## 1. 任务模型

**用户**：国服守望先锋玩家，每次打完一晚后复盘，也会查队友、对手和朋友。每天使用，是熟练用户；复盘时注意力集中在结果上，不想被弹窗打断。

**目标**（用户的话）：
1. 刚打完的几局，输赢是我的问题，还是队友、对手更强？
2. 这个玩家（自己、队友、对手）到底什么水平？
3. 我这个赛季在进步吗，该主玩哪个英雄？
4. 把数据拿出去做进一步分析。

**对象**（领域模型，来自 `watch-core::ir`）：

| 对象 | 关键属性 | 状态 |
|---|---|---|
| 玩家 | BattleTag、bnetId、头像、荣誉等级、游戏时长、总场次 | 正常 / 账号暂停 |
| 生涯快照 | 模式 × 赛季 × 职责：当前段位、最高段位、场次、胜率、KDA | 缺失赛季 = 未知（不是 0） |
| 对局 | 结果、地图、英雄、职责、比分、消灭/助攻/阵亡、伤害、治疗、阻挡、段位快照 | 列表行（摘要）/ 详情（10 名参与者） |
| 参与者 | 名字、英雄、职责、数据、段位、威能、组队 | 段位可能缺失 |
| 英雄使用 | 场次、胜率、KDA、时长、每 10 分钟数据 | 样本过少 |
| 对局强度 | 己方/对方/全场 × 综合/重装/输出/支援 的段位分均值 | 来源：对局内段位 / 生涯段位；未评定玩家不计入 |
| 数据集 | 采集时间、读取页数、详情成功数、失败请求 | 完整 / 部分 / 过期 |

全部为只读的派生数据。界面只提供查询、筛选、排序、导出，没有编辑。因此不做检查器面板，也没有"保存"概念。需要明确标出的是每个数字的来源与覆盖范围。

**动作**：查找玩家（频繁，无风险）、打开对局（频繁）、切换模式（频繁）、筛选/排序对局（频繁）、更新对局（常见）、刷新（常见）、导出数据集（偶尔）、移除玩家（偶尔，可撤销）、管理账号（罕见，涉及凭据）。

**主流程**（◆ 决策，· 机械）：
1. · 启动后自动恢复上次的玩家、标签页、模式
2. ◆ 在对局列表中找到想看的一场（结果、英雄、地图、数据一眼可比）
3. ◆ 打开它，对比双方 10 人的数据
4. · `[` / `]` 翻到上一场、下一场
5. · Esc 返回列表，位置、选中项、筛选原样保留
6. ◆ 需要时切到"对局强度"，看这几局的队友与对手

**次要**：英雄、赛季走势、档案、导出。**罕见**：账号设置、请求记录。

**频率 × 出错代价**：查看对局（每轮 × 无）→ 无确认，全键盘；移除玩家（偶尔 × 低）→ 撤销条而非确认框；账号凭据（罕见 × 高）→ 显式保存、token 不回显；导出（偶尔 × 低）→ 写新文件不覆盖，结果显示完整路径。

**恢复点**：重启后恢复玩家、标签、模式、导航栏宽度、主题、密度；对局列表的滚动位置和筛选在会话内保留。

## 2. 术语表（一概念一词）

| 概念 | 用词 | 不用 |
|---|---|---|
| 一场比赛 | 对局 | 战绩、记录、比赛场次 |
| 竞技比赛 / 快速比赛 / 角斗领域 | 模式 | 队列、玩法 |
| 重装 / 输出 / 支援 | 职责 | 位置、定位 |
| 己方 / 对方 | 己方、对方 | 我方、敌方、红蓝方 |
| 段位 / 段位分 | 段位、段位分（500–5000） | 等级、MMR |
| 对局强度 | 对局强度 | 实力、匹配强度 |
| 阻挡 | 阻挡 | 减伤（`resistDamage` 是阻挡/减免的伤害量，不是次数） |
| 胜率 | 胜 ÷ （胜 + 负），平局和未知不计入 | — |
| 未知值 | `—` | 0、N/A |

语气平实、具体，不用感叹号、不拟人。每条错误说明：发生了什么、为什么、下一步、数据是否安全。

## 3. 信息架构

主要对象是玩家，用户先知道要查谁，再决定看什么，所以按对象组织。

```
窗口
├─ 全局导航（左，可折叠为 56px 图标轨）
│   ├─ 查找玩家（输入框）
│   ├─ 玩家库（已查询的玩家；↑↓ 选择，Enter 打开，Delete 移除并可撤销）
│   └─ 设置（账号与连接 · 请求记录 · 外观 · 快捷键）
└─ 玩家工作区
    ├─ 头部：身份 · 竞技段位（三个职责）· 模式切换 · 数据状态 · 刷新 · 导出
    └─ 局部导航（标签页，同一对象的 5 个视角）
        ├─ 对局      默认页，主工作面
        │   └─ 对局详情（独立页面，保留列表上下文）
        ├─ 英雄      本赛季英雄使用表
        ├─ 对局强度  分职责
        ├─ 成长      存活时长、Fleta、KDA 的局间折线和走势
        ├─ 赛季走势  各职责段位随赛季变化
        └─ 档案      身份、生涯各职责、行为、省榜
补充导航：命令面板（Ctrl+K）、菜单栏、快捷键参考（F1）。
```

深度 ≤ 3（玩家 → 标签页 → 对局详情）。主流程从启动到对局列表 0 次点击，到对局详情 1 次。

## 4. 交互模型

- **选择**：列表是一个 Tab 停靠点，用方向键移动当前行；Enter 打开；Home/End/PgUp/PgDn 翻动。
- **筛选**：结果、职责、英雄、地图，选项旁显示数量；搜索框做中文子串匹配；筛选条件显示为可逐个移除的标签；表尾和汇总行始终写"显示 N / 已读取 M 场"。排序和筛选只作用于已读取的对局，并写明。
- **读取对局**：第一次查询读完全部历史，先把表列出来；之后每次只补上新的对局，已读的直接用本机保存的。表头写"已读取 N 场"，读完写"已读完上游可用记录"。
- **窗格**：导航栏 + 工作面。宽度可拖动（8px 命中区，双击恢复默认），180–360px，Ctrl+B 折叠；窗口窄于 1100px 时自动折叠为图标轨。工作面最小 720px，导航栏让步。F6 在两个窗格间切换，当前窗格有可见标记。
- **撤销代替确认**：移除玩家后出现 7 秒的撤销条。
- **长操作**：段位在后台分小批查询，没查到的位置先显示"查询中"，查到后补上；对局强度只用已查到的段位计算，不再现场请求。非阻塞，可取消，期间其他页面照常使用。

## 5. 状态矩阵

每个数据区域都要有下列设计，没有的写原因。

| 状态 | 设计 |
|---|---|
| 初次加载 | 1 秒内什么都不显示（`Dur.loadingHint`，`AfterDelay`）；之后是沿用真实布局的骨架屏（共用的 `Skeleton`）。单个小区域或刷新用 `Spinner`；超过约 10 秒、分步骤的任务用步骤 + `ProgressLine` + 剩余时间 |
| 刷新 | 保留旧数据，表头角落显示小指示，不清空、不回顶 |
| 首次使用（没有玩家） | 说明这里放什么 + 查找框 + 若无账号则给"添加账号"按钮 |
| 没有账号 | 顶部横幅：先添加大神账号，按钮直达设置；查找框保持可用但提示 |
| 无对局 | 保留表头；"KCN#51896 在竞技比赛没有对局记录"+"切换到快速比赛"按钮 |
| 筛选后为空 | 列出生效的筛选条件 + "清除筛选"按钮；不与"无对局"混用 |
| 部分数据 | "已读取 3 页"；统计值写样本数 n；缺失字段显示 `—` |
| 错误 | 发生了什么 / 原因 / 下一步（重试、去设置）/ 数据是否安全 + 可复制的详情；有旧数据时保留并加横幅 |
| 会话过期 | 自动重新查找一次；失败再按错误处理 |
| 资料私密或不存在 | 业务错误单独文案，不显示为"零场" |
| 过期 | "采集于 14:32"；超过 5 分钟提示可刷新 |
| 未知与零 | `—` 与 `0` 不同；平均值写分母 |
| 离线（watchd 未启动） | 全局横幅 + 重试；说明本地服务未运行 |
| 控件态 | 悬停（`hover` 底色，叠在选中之上）、按下、聚焦（2px 强调色描边，只在键盘操作后出现）、选中（`selected` 底色 + 1px 强调色描边；标签页例外，用下划线）、禁用（次要文字色、无悬停、普通光标，悬停提示写原因）、只读（正常对比度，可复制）。全部由 `design/interaction.dart` 的 `ItemState` 与 `Pressable` 画，页面不自己画。左侧色条只表示数据（结果、胜率、严重程度），不表示选中 |

优先级（高→低）：阻塞错误、禁用、选中、聚焦（叠加）、过期/待处理标注、悬停、默认。

## 6. 对局强度的呈现

数据：每名参与者的段位分（500–5000）。竞技、角斗用对局内段位；快速比赛用读取这场时每位玩家本赛季的竞技段位快照，按该局他所打的职责取值（没有则取其他职责里最高的）。未评定玩家不计入。

- 顶部：按“本人职责”汇总的表（重装 / 输出 / 支援各一行）：场次、胜率、己方同职责均分、对方同职责均分、差值、综合差值。
- 逐场表：每场一行，列分组为 综合 / 重装 / 输出 / 支援，每组 己方、对方；末列写已评定人数。"差"只在双方都有评定时显示。
- 图：分段控件选 综合 / 重装 / 输出 / 支援，折线图画己方与对方，实线对虚线、蓝对橙，端点直接标注，胜局实心点、负局空心点。Y 轴不从 0 开始，轴范围写在图上。
- 覆盖说明始终可见："已评定 38 / 50 名玩家；12 名未定级或资料不可见，未计入。"

## 7. 视觉语言

**风格**：视觉语言取守望自己的（生涯与赛后界面：深蓝底、守望橙、斜切、六边形底纹），但保持数据工具的克制——形状和底纹只用在固定的几处，正文区仍是平的面、细线和留白。工作区结构取 DaVinci Resolve 的"来源—工作面"，列表键盘交互取 Linear，快捷键与命令注册取 JetBrains。

**色彩原则**：
- 每种颜色只表达一种含义，且都有文字或形状的冗余通道。
- 结果：胜 ✓ / 负 ✕ / 平 –，文字写出，颜色为辅。
- 己方 / 对方：位置分组 + 文字标签；颜色用蓝 / 红，和游戏里的蓝队红队一致（色觉检查见下）。
- 伤害、治疗、阻挡用三种色相（红、绿、蓝，`statDamage` / `statHealing` / `statMitigation`），与 [product-design.md](product-design.md) 一致；三者总有文字标签或列头，颜色只帮助扫视。"最高"另用文字标出。（早先这里写的是"同一中性色"，与产品设计和代码不符，2026-10 统一为三色。）
- 强调色（守望橙）只用于聚焦、选中、主按钮，以及图表里的主系列。
- 一张图里同一事物的两条线（如"赛季末 / 最高"、"每局 / 10 局平均"）：主系列强调色，参考系列次要文字色且用虚线；不借用己方 / 对方的蓝红。
- 状态色：成功绿（`success`，步骤完成、连接正常）、警告琥珀、错误红，不与图表数据系列混用，也不借用胜负色。
- 变化好坏：`positive` / `negative`（趋势卡、差值），与胜负色分开命名。
- 色觉检查：己方 / 对方、主 / 参考系列在红色盲、绿色盲、蓝色盲模拟下的色差由单元测试检查（`test/design_rules_test.dart`）；页面里不得直接写颜色字面量，同样由测试检查。

令牌的权威来源是 `app/lib/design/tokens.dart`，此表随之更新。

**形状语言**（issue #56，2026-10）：只有两种形状，都在 `design/shapes.dart`。
- **斜切**（`SlantBorder`，每单位高度横移 `slant` = 0.2，约 11°）：一切“被选中 / 被按下 / 说出结果”的东西——选中的标签页是实心橙色平行四边形，分段按钮的轨道和选中段、按钮、页面上的筛选标签、头像下的胜负条、小节标题前的短标（`SectionMark`）。
- **切角**（`CutBorder`，右上角切掉 `cornerCut` = 10）：面板（`Panel`）、卡片（`CardSurface`）、页首横幅（`HeadlineBand`，切 20；底纹在图片下面）。
- 圆角几乎不用（`Radii` 都是 2）。直立的左侧色条只给带数据含义的地方（结果、胜率、严重程度）；小节标题用斜的短标，两者不再长得一样。

**材质**：自己的底纹是极淡的六边形网格（`HexBackdrop`），从右往左渐隐，右上角一团主题色（或英雄色）的光晕。只铺在页首（玩家头部 + 标签栏）和 `HeadlineBand` 后面，正文区是平的实色面。

**图片**：每页只在页首放大图。列表行（对局、英雄）是平的面，图片是右侧一条斜切左边缘的图带（`ArtRow.stripShare`，行宽的一半），斜边处最清楚、到右端消失，落在名字和数字之间的空白里，不压文字。

**图标**：Material 图标统一用直角（Sharp）一套，和游戏的实心职责图标同一种气质。

**共用组件**（页面只用这些，不再各写一份）：

| 组件 | 用途 |
|---|---|
| `Pressable`、`ItemState`（`interaction.dart`） | 一切可点选的东西的悬停、选中、聚焦、禁用 |

| `HeadlineBand`、`HeadlineFigure`、`RecordText`（`headline.dart`） | 页首的视觉锚点：英雄横幅或地图从右侧渐入、深色遮罩、六边形底纹和英雄色光晕、右上切角、左边一道主题英雄色的竖条，上面一行大号数字；概览、每日总结、常遇玩家、英雄对比、回顾都用它 |

| `Skeleton`、`AfterDelay`、`Spinner`、`ProgressLine`、`RefreshingChip` | 加载的各种情形（见状态矩阵） |
| `EmptyState`、`ErrorPanel`、`StatusBanner` | 无记录、失败、页内提示 |
| `SegmentedBar` | 单选的一组选项：斜切的轨道，选中段是实心橙色（明度变化加粗字，不只靠色相）；`onChanged` 为空即禁用，`disabledReason` 说明原因 |

间距：4、8、12、16、24、32。圆角：都是 2；形状靠斜切和切角（见上）。动效只用来帮人看出“什么变了”，不做装饰（组件在 `design/motion.dart`，时长在 `Dur`）：

| 情形 | 做法 | 时长 |
|---|---|---|
| 悬停、按下 | 底色 | 100ms |
| 数值在原地变化（`KpiTile` 等） | 新值淡入（`AnimatedValueText`）；第一次出现不动画，数字不从 0 滚起 | 160ms |
| 换标签页、换玩家、列表 ↔ 详情、上一场 / 下一场 | 淡出淡入，新内容上移 6px（`FadeThrough`）；切模式不重建页面，保留排序等选择 | 进 200ms，出 100ms |
| 刷新后列表里新出现的对局 | 只有新行淡入上移（`ArriveOnce`），已有的行不动 | 300ms |
| 折线图首次显示或换了数据 | 从左往右画出（`RevealLeftToRight`）；悬停、键盘移动不重放 | 300ms |

退场比进场短；没有超过 300ms 的动画；减少动画偏好下全部归零，所有功能都不依赖动画结束。暂未做：列表到详情的共享元素过渡（详情页是原地替换，不是导航路由）、排序时行的位置插值（列表是虚拟化的）。

**字体**：Microsoft YaHei UI（中文）+ Segoe UI（数字，开启等宽数字）；大号数字（`Ty.display` 44、`Ty.figure` 26、`Ty.posterFigure` 38）用 Bahnschrift 窄体（`wdth` 78）700 字重，数字是页面的主角；正体（试过斜体：Bahnschrift 没有斜体，合成的倾斜太大）。字号全部来自 `Ty`：10（标签里的小字、▲ 标记）、12（说明）、13（正文与表格）、15（章节标题）、16（卡片标题）、20（页面标题）、26（数字卡片）、44（页首大数字），另有英雄海报专用的 38 与 68；字重 400、600；页面标题、章节标题、大号数字、选中的标签和分段用 700。中文行高 1.5，表格单元行高固定。数字列右对齐、固定小数位；单位写在列头；百分比写分母。

**密度**：表格行高 紧凑 34 / 标准 44 / 宽松 52（只改垂直内边距，不改列宽），其余列表（有对局的日子、常遇玩家、共同对局、当天对局）的上下内边距跟着变。默认标准。

**控件高度**：三档，`Ctl.small` 28（分段、筛选标签、ⓘ、菜单栏）、`Ctl.regular` 32（按钮、图标按钮、筛选菜单）、`Ctl.large` 36（标签页）。**间距**：`Sp` 的 0 / 2 / 4 / 6 / 8 / 12 / 16 / 24 / 32，页面里不写别的数（`test/design_rules_test.dart` 检查）。**透明度**：`Alpha` 的 0.14 / 0.5 / 0.7 / 0.9。**对话框**：都用 `AppDialog`：标题行右侧是关闭按钮，操作在右下，安全的在前、主要的或危险的在后；删除类用 `confirmDanger`，危险按钮是错误色。**英雄色**：当作文字时用 `legibleOn` 保证 4.5:1，当作图标或色条时 3:1。

**图表**：全部自绘并读取主题令牌。柱状图从零开始；折线图的非零基线要标注；比较用的小图使用同一刻度；系列数 ≤ 5；每张图有文字摘要，并可切换为表格；悬停显示精确值，但静态图本身已说明主要结论。

按问题选图（组件在 `design/charts.dart`、`design/chart_kit.dart`）：

| 问题 | 图 | 要点 |
|---|---|---|
| 一局一局怎么变 | `LineChart` | 直接标注；空缺不连线；`band` 画“通常范围”（个人基线），落在带外的点才值得看；`stepped` 用于段位这类保持到下次变化的值；同一页的几张图传同一个 `sync`，指向一局就都显示这一局 |
| 大致往哪走 | `Sparkline` | 无坐标轴，只表示方向，紧挨着它说明的数字 |
| 这些里哪个最高，差别算不算数 | `IntervalBars` | 从 0 起；细线是区间；每个值旁写场次；可画一条参考线（50% 或总胜率）；样本不足的条目变灰，只列出、不参与比较；每行可点击下钻 |
| 什么时候打得好 | `HourHeatmap` | 星期 × 小时；按离中线的距离着色（正负两色）；少于 3 场的格子不着色 |

不用饼图和环形表盘：读不出比较。

## 8. 无障碍与国际化

- 所有交互元素有名称；对局行读作"胜利，66号公路，金驭，3比0，消灭9助攻11阵亡3"。
- 表格每个区域一个 Tab 停靠点，内部用方向键。
- 文字放大到 200% 时行高随内容增长，不裁切。
- 全部文案走一份字符串表 `app/lib/l10n/`（`tr.<区域>.<条目>`，规则写在 `strings.dart` 开头）：一句话一个条目、变量作参数，不拼接片段；被查询的玩家多数句子省略主语，必须区分时称“本人”；游戏和大神的数据（英雄名、地图模式名等用来匹配的值）不进表。数字用 `intl` 的 zh-CN 格式。
- 所有文字令牌对所有可用底色的对比度由单元测试检查。

## 10. 复盘：对局列表为什么会臃肿，以及怎么用 skill 的原则避免

第一版的对局列表有 11 列（结果、时间、地图、英雄、职责、比分、消助阵、伤害、治疗、阻挡、段位），每个数字都是对的，但玩家看不出"这是哪一局"。问题不在视觉细节，而在更早的阶段。

### 根因，对应到 skill 的条目

| # | 做错了什么 | 违反的原则（出处） | 应当怎么做 |
|---|---|---|---|
| 1 | 任务模型里把"找到一局"和"比较多局"写成了同一步（"数据一眼可比"），于是直接套用"分析工具用表格" | 表格要靠"用户的核心问题是不是在某个属性上比较谁最大"来判定；如果靠外观认出对象，该用图像行（`patterns/tables.md` 决策流程第 4 问与 tiebreaker）。任务要拆到"动词 + 对象 + 结果"，每个元素都要能追溯到一个任务（`ux/users-goals-tasks.md`） | 列表的任务是"认出这一局"，核心问题是"是哪一局"，所以是识别面 |
| 2 | 没有做"属性 × 任务"的分配，所有属性默认堆进列表 | 检查面的结构应镜像对象的语义分解（`ux/information-architecture.md`）；渐进披露发生在面板级，不是控件级（`ui/density.md`）；三个元素在争抢注意力，其中两个是错的（`ui/visual-hierarchy.md`） | 先给对象的每个属性指定它服务的任务，再决定它放在哪一层（见下表） |
| 3 | 把"密度"当成目标 | 密度的合理性来自"需要同时看到多行才能完成任务"；识别任务要的是少而大（`ui/density.md` 的判定规则） | 识别面行高 ≥ 80px，每行 ≤ 4 项信息 |
| 4 | 中文、数字用两套字体混排，文字和图标错位 | 字号和行高要以最难的文字（中文）为准；回退字体会让每一行的高度改变，进而撑破固定行高（`ui/typography.md` 的 CJK 与数字部分） | 一套主字体覆盖中文、拉丁和数字；显式行高；等宽数字 |
| 5 | 图标用得不加区分 | 领域已经标准化的图标要原样复用；先问这个概念值不值得一个图标：它是否出现在密集重复的场合（`ui/iconography.md`） | 职责、地图、段位在每一行都出现，值得用图；"伤/疗/挡"汉字徽标不减少文字，不用 |

### 属性按任务分层（以"对局"为例）

| 属性 | 服务的任务 | 放在哪一层 |
|---|---|---|
| 结果、比分、地图、英雄、时间 | 认出这一局 | 列表行 |
| 消灭/助攻/阵亡、伤害、治疗、阻挡、最后一击、威能、组队、阵容、禁用 | 判断这一局打得怎样、和 9 个人比 | 对局详情 |
| 己方与对方各职责的平均段位 | 判断对手强不强 | 对局强度页 |
| 多局的平均数据、胜率 | 判断最近状态 | 档案页的"近期表现"，列表只保留战绩 |

### 三种表面，各有各的写法

| 表面 | 回答的问题 | 写法 | 用在 |
|---|---|---|---|
| 识别面 | 是哪一个？ | 图像 + 名称 + 至多 2 个关键事实；行高 ≥ 80；不设数值列、不设列排序 | 玩家库、对局列表 |
| 比较面 | 哪个最好、最差、不一样？ | 表格；数字右对齐、等宽、固定小数位；列头可排序；**每行第一格必须是识别模块**，让人知道这一行是谁 | 队伍表、英雄统计、强度逐场表、赛季数据 |
| 检查面 | 这一个的全部是什么？ | 按对象的语义分组，只读，明确区分"缺失"与"零" | 对局详情、英雄统计面板、档案 |

### 一致性规则

1. 同一个对象在任何地方使用同一个识别模块（地图图 + 比分 + 英雄）。强度逐场表的第一格因此也要带地图图，而不是只写时间。
2. 解释性文字进 ⓘ。**问题性文字保留文字和图标**：数据没读完、刷新失败、覆盖率不足，这些必须一眼可见（`patterns/states.md`、`evaluation/heuristics.md` 的 Scale honesty）。
3. 图标只用三类：通用符号、领域自带的标准图标（职责）、能帮助识别的图像（地图、英雄、段位）。每个图标有无障碍名称和提示，职责列头带图例（`ui/iconography.md`）。
4. 新页面开始画之前，先写这一页是识别面、比较面还是检查面，并列出每个属性服务的任务。

## 11. 后续迭代的设计决定

第一版之后又定下来的做法，新页面按这些来。

**英雄：列表识别、详情阅读。**
- 英雄列表沿用对局列表的识别行：英雄横幅作背景并向右渐隐，左边是方形头像，竖条按胜率上色，右边只放三个大数字（场次、胜率、时长）。排序依据决定“再多显示哪一个数字”，其余数据放进详情页，列表不堆列。
- 点开是二级页面，不是底部边栏：空间服从任务复杂度。版式是海报：英雄横幅作背景，立绘放左边不遮背景，右边是大号的英雄名和数字，不用方框；强调色取自游戏里这个英雄自己的颜色。
- 详情页自上而下：身份与总览 → 赛季数据 → 近期对局 → 技能与威能。每节标题左侧用英雄色的竖条。

**缺失数据要有统一的说法。** `—` 是这个英雄无法产出；灰色 `0` 是能产出但上游没记录；`≈` 是推算或取自近期对局；胜率样本少于 5 场变灰。规则在 [algorithms.md](algorithms.md) 第 6 节，界面只用符号，解释放在悬停和说明里。

**强度图。** 平均之外要给分布：每场一根竖条（锐角矩形，像 K 线），表示该队已评定玩家的最低到最高；纵轴用段位名而不是分数，分数和区间放在悬停里；中间缺数据的场次用斜线阴影带连起来，说明“这里没有数据”而不是图坏了。职责筛选按“本人所打职责”，没打过的职责不出现。

**等待要看得见。**
- 长操作显示分步进度、当前对象、已用和约剩时间，可取消。
- 图片到达前显示同样大小的占位块，布局不跳；同一张图只下载一次、只解码一次；加载超过约 0.35 秒才在状态栏出现进度，避免缓存命中时闪一下。

**滚动条不压内容。** 滚动条有自己的一条 12px 的槽。表格的表头、行和合计行一起让出这条槽，列才对得齐。

**措辞。**
- 一句话说一件事；界面里的说明不超过两句，原理和公式放文档。
- 先说是什么、结果怎样，再说原因；不重复界面上已经看得见的内容。
- 空状态写发生了什么和下一步能做什么，各一句。
- 同一个概念同一个词：“对局强度”“段位分”“已评定”“职责”在全应用保持一致（见第 2 节术语表）。
- **口吻是游戏数据工具，不是在解释自己的 AI**（issue #58，2026-10）：
  - 标签用玩家的词：强势图 / 苦手图、绝活、短板英雄、连胜中、零阵亡、同分段、段位同步、高光时刻、战报。
  - 只给事实和数字：不劝告（删掉“可以考虑休息一下”）、不安慰（“输得不全在该玩家”）、不评价人（“打得吃力”）。
  - 说明先写口径，用“横条：…；细线：…”这种短句并列，不用冒号串长句；并列的事实用中文逗号分隔（“段位同步中，剩余 6 场”），标题里的附加信息用空格或括号（“每日总结 2026-10-22 周四”“玩家库（12）”），不用 · 这类中缀符（测试检查）。
  - 不写界面在自我说明的句子：“只有……才会出现”“会随之生成”“这里会”。
  - 主语能省就省，必须区分时用“本人”；数据来源写“大神”，不写“上游”；“同侪”改“同分段”，“可能的范围”改“置信区间”。
  - 统计方法名（Mann-Kendall）只出现在悬停说明的括号里，界面上写“显著 / 弱趋势 / 无变化”。
  - 空状态：一句事实 + 一个去处按钮（“$mode还没有读取对局。” + “去对局页读取”）。


**概览：一屏讲完一个人。**（2026-10，参考了大神战绩工具的构图，风格不同）
- 第一个标签页，打开玩家时先看到它。只用本机已读取的对局，打开就有。
- 页首是视觉锚点（`HeadlineBand`）：最近最常用英雄的横幅向左渐隐，竖条是这个英雄自己的颜色，上面一行大号数字（`Ty.display`，44px，只给这几个数字用），每个数字下面写“比之前 20 场”的变化，涨绿跌红，胜率旁边有迷你走势线。
- 最近 20 场用英雄头像加胜负条识别，点开即详情；地图、英雄用区间横条，点一行即筛选对局列表：每个区块都通向下一步。
- “值得注意”只放证据足够的结论，没有就明说没有；不用环形表盘。（这里原先还写了不用斜切和六边形底纹，issue #56 改为采用，见第 7 节“形状语言”。）

**统一页首与数字（issue #43，2026-10）**：
- 每个页面一个视觉锚点，用同一个 `HeadlineBand`：每日总结用当天最常玩英雄的横幅，常遇玩家的队友详情用他在共同对局里最常玩的英雄，英雄对比两边各用自己的英雄，回顾的每一步用这一步的英雄或地图（最强图揭晓后才显示地图）。没有图片时只有遮罩和竖条。
- 主数字用 `HeadlineFigure`（44px 窄体），次要数字才用 `KpiTile`；战绩写成两个数字（`RecordText`：“15 胜 20 负”的数字大、字小），带单位的数字用 `FigureText`，不让“小时”“分钟”撑宽一列。
- 每日总结：当天对局在头部下方排成一排头像；“全场 10 人里最高”合成一条（消灭 ×3、伤害 ×5 …），其余高光卡片按宽度均分成列，右侧是这一局英雄的头像渐入，数字用 26px 窄体并着色。
- 地图详情：胜率和战绩放大，其余是小卡片。
- 英雄对比的选择器照游戏里的选英雄界面：全部英雄的方形头像，按职责一行一组（和当前英雄同职责的在前），头像下一道英雄色条、名字和本赛季场次；本赛季没玩过的英雄是灰色头像，不能选；当前英雄描边并写“当前”。
- **滚动条不压内容**：每个纵向滚动区域在右侧留出 `scrollGutter`（16px）给滚动条，内容的右边距从这条之外算起；`test/design_rules_test.dart` 检查每个 `ListView` / `SingleChildScrollView` 都留了这条（不滚动或横向滚动的除外）。
- **更新内容的排版**（`ReleaseNotes`）：去掉与对话框标题重复的版本标题；每一类（新增 / 修复 / 变更）是带色条和条数的小标题；每条以加粗的名字开头，issue 号做成小标签，说明另起一行用次要色和 1.7 倍行高；子项缩进并用短横；行内代码用等宽字体加浅底，链接用强调色并可点击；整段可选中复制。
