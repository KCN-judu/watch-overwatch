## 2. 界面文字

对照 Material、Apple HIG、Microsoft 写作指南、NN/g 与 WCAG 3.3。

### 高

1. **错误信息直接露出服务端或异常原文，且大多没有下一步。** `api.dart:73,84,87,362,376`、`widgets.dart:651`、`settings_page.dart:103,247`、`app_state.dart` 多处 `…：${e.message}`、`navigator_pane.dart:88`、`player_view.dart:287,563`；后端文案带尾部空格和术语（`service.rs:247`、`main.rs:302` 的 `role_id`）。建议按错误类型给固定文案，格式“发生了什么 + 怎么办”，原文只放在“复制详情”里。
2. **标签和实际动作不一致。** “强制刷新”实际是重新查询段位；“刷新数据”在强度页还会重新分析；“继续读取”提示却说读全部；“上一场 / 下一场 / 返回对局列表”也用于英雄；“取消”不说取消什么；“命令面板”用了 Mac 的 ⌘ 图标。
3. **关键信息只能悬停才看到。** 为什么有场被排除、某职责场数不够、`≈`、灰色 `0`、`—` 的含义、胜率公式、“已读完”的含义等（`strength_page.dart:171,181,213,227`，`hero_detail_page.dart:492-502`，`matches_page.dart:696,733,769`，`match_detail_page.dart:202` 等）。应放进可见的说明行，悬停只补充。
4. **内部术语未解释。** 大神、上游、接口、状态码、排队 ms、采集于、统计目录里没有名称、`× 600 ÷ 场均时长`、`docs/credentials.md`；强度页上的“已评定 / 无人定级”。
5. **用词不统一。** 段位 / 段位分 / 分数 / 评分；已评定 / 已定级 / 有段位；读取 / 加载 / 取 / 查询 / 采集 / 获取；缓存 / 本机缓存 / 本地已保存；刷新 / 强制刷新 / 重新分析；搜索 / 筛选；档案 / 玩家资料。
6. **“你”被用来指任意被查询的玩家。** 强度页和英雄详情多处写“你所打的职责”，应改成“该玩家”。

### 中

模式名叠字（“快速比赛没有读取到对局”）；日期没有年份、时长有三种写法（`1 小时 5 分钟` / `1.2 小时` / `m:ss`）、`ms` 与 `毫秒`、赛季有 `第 5 赛季` 与 `S5` 两种写法；中日韩文字与数字之间的空格不一致；双空格当分隔符；公式写成 `胜 ÷ （胜 + 负）`；`Kills / Assists / Deaths` 英文混入；进度文字重复；空状态里有“可…”之类的填充语；设置页文案（如“token 留空不会保留旧值”自相矛盾）；菜单分类（“导出数据集”放在“文件”下、“表格密度”与“表格行高”）；无障碍标签（`己` / `对` 单字表头、`移除筛选：结果：胜`）；整句拼接、没有复数和占位符，无法本地化；`重试` / `重新分析` / `继续读取` 没说重试什么。

### 建议统一的词

段位（档位名，如“白金 2”）/ 段位分（数字，不再用评分、分数）/ 已定级、未定级；对局（对象）、场（数量）；读取（取数据）、加载（仅图片）、查询（仅逐个玩家的段位）、更新于；本地缓存；刷新（重新读取）、重新分析、重新查询段位、重试（仅用于失败后）；账号、玩家；搜索（文本框）、筛选（标签与分类）；移除（列表项、账号）、清除（缓存、筛选）；综合（全部职责）；己方 / 对方；第 N 赛季；该玩家。

## 3. 界面一致性

### 高

1. **“选中”有八种画法**：表格行（底色 + 3px 左条）、卡片（1px 描边 + 底色）、玩家列表、侧栏、命令面板、标签页（2px 下划线，焦点环就是底色）、分段控件（底色 + 对勾）、筛选标签。规范写的是“底色 + 左条”。
2. **悬停、焦点、光标不统一**：分段控件、标签页、可排序表头没有悬停底色；`FilterTag` 和选中的筛选标签的不透明底色盖住了悬停；玩家列表没有点击光标；`InfoTip` 不能键盘聚焦；焦点指示有四种。
3. **组件被复制分叉**：`KpiTile` 与 profile 的 `_Tile`（宽 150 / 176、背景不同）；对局卡与英雄卡复制了同一段遮罩，透明度已漂移（0.70/0.25 与 0.72/0.30），立绘左右位置、名字字号也不同；返回列表的头部在对局详情和英雄详情各写一份，设置页用另一种“返回”。
4. **卡片和面板约 12 处各自包边框**，内边距有 12、16、20、24 等多种。
5. **章节标题没有共用组件**：多数页用 `Ty.section`，英雄详情用带色条的标题，设置页用 `bodyStrong`，间距也有 24 与 32 两种。
6. **加载状态有六种画法**：骨架屏、表格骨架、卡片骨架、详情页自己的色块、整页居中的“刷新中”小标、强度页自己的运行面板；转圈有 12、14、16 三种大小，进度条有 3、4 两种高度；英雄详情页没有加载状态，主题色会闪一下。
7. **空状态和错误状态各页自己做**：很多地方用纯文字代替 `EmptyState`，`StatusBanner` 只在壳层用了两处。
8. **颜色用错了含义**：趋势图用己方蓝、对方橙表示“赛季末”和“最高”；设置页和强度页用胜利绿表示“就绪、成功”；`dataBar` 令牌没人用；伤害、治疗、阻挡在规范里是同一个中性色，代码里是三种。
9. **行为问题**：分段控件没有禁用状态，分析进行中看起来可点但没反应；热门英雄与对局页的搜索框功能不同（后者有 Ctrl+F、清除按钮、语义标签）。

### 中

控件高度形成一串阶梯（24、28、30、32、34、36、39）；原生 `OutlinedButton`、`DropdownButton`、`CheckboxListTile`、`ExpansionTile`、`SnackBar` 没有套主题；三种对话框写法、按钮位置不一、没有危险操作样式；`Ty` 之外还有 9、34、68 号字，字重有 400/500/600/700/800 而规范只有两种；大量间距写死数字（`SizedBox(width: 4)` 21 处等）；滚动条留白 12 与 16 与 8；缺失值符号有 `—`、`无数据`、`没有数据`、`?` 四种；时长、字节、日期格式没走统一函数；行高与规范文档不一致，只有表格响应密度设置；亮暗主题下的透明度写了成对的字面值，英雄色直接当文字色没有对比度处理；说明提示有三种形式；多个控件命中区小于 28px；图表内的边距和透明度写死、同一段说明在每个图下重复。

### 低

行分隔线三种；3px 左条表示四种意思；`▲` 在两处含义不同；缩略图尺寸与圆角各处不同；设置页行距 3 与 4 混用；`Ty.page` 只在部分页面使用；若干写死的圆角 4。

## 4. 建议的处理顺序

1. 数据：赛季交替校正、趋势页本机缓存、刚结束对局的详情处理。
2. 文字：错误信息统一改写；统一词汇表；去掉“你”；把只在悬停里的关键说明放到可见处。
3. 一致性：先做共用的“可点击表面”（选中 / 悬停 / 焦点 / 光标）、`Panel`、`SectionHeader`、加载与空状态；再收敛颜色和字号令牌。
