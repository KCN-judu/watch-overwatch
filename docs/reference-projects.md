# 对标项目

本项目参考了 Overstats。这一页写清楚它是什么、我们用了它的什么、哪里不一样、哪些功能还没有做。

## Overstats 是什么

一个 Python 写的本地数据服务和聊天机器人后端，封装网易大神的接口，对外提供 HTTP API：玩家资料、战绩列表和详情、段位历史、强度分析、双人同玩，并能把结果渲染成图片发到群里。它还附带一批和大神无关的模块：商店、赛事、补丁、英雄百科、选取率、地图猜题，以及用大模型做自然语言路由和点评。

它是本项目最重要的参照：大神接口怎么调、返回什么字段，我们最早都是从它的抓包文档和代码里弄清楚的。

## 我们用了它的什么

| 内容 | 怎么用的 |
|---|---|
| 大神接口的抓包文档（`src/client/api_structure`） | 作为转换代码和测试夹具的依据；`crates/watch-core/tests/ir.rs` 里的样例按它整理 |
| 多账号轮流使用、失败后冷却的思路 | 在 `scheduler.rs` 里重写：并发、限速、冷却、重试，规则见 [algorithms.md](algorithms.md) |
| 英雄、地图、统计项目录（`query_tool.json`） | 精简后内置为 `query_tool.min.json` |
| 熟练度徽章图 | 沿用，放在 `app/assets/levels/` |
| 获取 role_id 和 token 的做法 | 见 [credentials.md](credentials.md)，我们重新写了一份 |

职责图标最早也取自它的资源，后来换成了从游戏里解包的官方矢量图。

## 和它的主要区别

| | Overstats | 本项目 |
|---|---|---|
| 形态 | Python 服务，结果主要是图片和 JSON，给机器人用 | Windows 桌面程序，给自己看 |
| 数据结构 | 各模块直接处理上游 JSON | 先转换成统一的数据结构（IR），界面和分析都只读 IR |
| 缺失数据 | 各模块自行处理 | 缺失就是缺失，不当 0；补全规则集中在一处并在界面标出 |
| 对局强度 | 快速、竞技各一个模块 | 按“你自己打的职责”分组，每个职责各取最近 N 场，逐场画出平均和最低到最高的分布 |
| 凭据 | 写在 `config.py` 里 | 只存本机的用户目录，在界面里添加，不进导出和日志 |
| 英雄资料 | 依赖外部接口 | 来自本机安装的游戏，名称和说明与国服一致 |

## 还没有迁移的功能

这些在 Overstats 里有，我们的服务端（`watchd`）或旧网页界面里有一部分，但 Flutter 界面还没有：

- 双人同玩列表和详情
- 省榜、英雄榜查询
- 英雄选取率榜和历史曲线
- 商店、赛事、补丁、英雄百科、地图猜题
- 总结图片、机器人回复、AI 点评、自然语言路由

不要把本项目描述成 Overstats 的完整替代：它覆盖的是“查一个玩家、看对局、分析强度”这条主线。

## 迁移时修掉的旧问题

| 旧问题 | 现在 |
|---|---|
| 所有账号都在冷却时仍然发请求 | 等到最早可用的时间 |
| 较早的成功清掉了较新的冷却 | 成功不改冷却 |
| 并发失败互相覆盖 | 同一凭据延长冷却，并叠加认证停用 |
| 历史采集吞掉异常 | 每个赛季单独记录成功或失败 |
| 页面显示迟到的旧响应 | 请求带序号，旧响应不覆盖新页面 |
| 请求无限堆积 | 有排队容量、截止时间和响应大小上限 |
| 读取失败被当成 0 场 | 明确报错 |

当前的范围限制：趋势最多读 6 个赛季；读取失败显示错误，不伪装成零场；公共资料页（旧网页界面）依赖外部页面，结构变化时会显示失败。
