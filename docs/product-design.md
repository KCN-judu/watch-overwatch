# 产品设计

## 对象与任务

玩家有持久的查询身份；一场对局有地图、结果、两支队伍；每名参赛者关联英雄和统计。统计可能缺失，零不是缺失。英雄目录可能没解析出某个英雄，不猜它是谁。

主要任务：反复查询熟悉的玩家，找到一场对局，比较队伍贡献，再回到列表继续看。设计假设是经常复盘；技术数据不进主流程。

## 从用户反馈推出的规则

| 用户给出的细节 | 规则 | 同思路的其他设计 |
| --- | --- | --- |
| 对局详情进入独立页面 | 空间服从任务复杂度，主任务占主区域 | 英雄详情、玩家对比有足够空间；侧栏只放简短的辅助信息 |
| 双方两色 | 沿用游戏里己方蓝、对方红，不用重新学；颜色总配位置分组和文字标签（色值和色觉检查见 [界面设计](ui-design.md) 第 7 节） | 职责名称、胜负文字、地图与模式全应用一致；颜色不替代文字 |
| 伤害、阻挡、治疗最高值 | 帮人发现差异，省去逐格心算 | 趋势给同口径的变化；比较突出差值，同时给样本量 |
| 英雄立绘脸部 | 图形加快身份识别 | 对局列表保留英雄和地图的识别线索；装饰不遮挡姓名和数字 |
| 已查玩家重启后可选 | 记住重复的操作 | 返回时保留页码、筛选和滚动位置；动作完成后给明确反馈 |
| 数字和排版对齐 | 比较是一条阅读路径 | 同一指标列序、单位、数字对齐方式固定；不同页同一含义用同一写法 |

## 表现和状态的约定

- 层次：主层是当前对象和核心数据；次层是比较范围、筛选条件；末层是来源、时间、技术细节。
- 己方蓝、对方红是展示约定，不代表大神记录的实际阵营。伤害红、阻挡蓝、治疗绿；最高值有文字标注。
- 最高值只比较同队已给出的数值；并列的都标；全零或全缺失不标。数据不全时，它只是已给出数值里的最高。
- 加载、失败、无记录、部分缺失是四种不同状态。失败可以重试和返回；迟到的响应不覆盖新页面。
- 图片是识别线索，没有图片仍能读出姓名、英雄和统计。英雄头像和肖像取自目录，缺了依次用大神的封面图和小图标。
- 宽窗口里两队并排；空间不够时上下排列，不压缩或截断核心数字。
- 新页面验收检查：第一眼看到什么，比较要几次视线往返，返回是否丢上下文，缺失数据会不会被误读，键盘能否操作。

## 其他页面沿用的原则

生涯以常用英雄和同模式样本为中心；趋势用一致的时间和赛季口径；导出写明范围、完整性和昵称、英雄的对应；设置页围绕连接状态和能执行的恢复操作。只强调有意义的差异，不把所有数值都染色。
