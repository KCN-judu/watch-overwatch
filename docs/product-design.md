# Watch Overwatch 产品设计约定

## 对象与任务

玩家有持久化的查询身份；一次对局包含地图、结果、两支队伍；每名参赛者关联英雄和统计。统计可能缺失，零不是缺失。英雄目录可能未解析，不能猜测英雄身份。

主要任务是重复查询熟悉的玩家、定位一场对局、比较队伍贡献，再返回列表继续查看。以经常复盘为设计假设；不把技术数据展示当成主流程。

## 从用户反馈推导出的规则

| 用户给出的细节 | 产品应注重什么 | 同思路的其他设计 |
| --- | --- | --- |
| 对局详情进入独立页面 | 空间服从任务复杂度；主任务获得主区域 | 英雄详情、双玩家比较应有足够空间；侧栏只承载简短辅助信息 |
| 红蓝双方 | 借用玩家熟悉的游戏语义，减少重新学习 | 职责名称、胜负文字、地图与模式保持一致；颜色不能替代文字 |
| 伤害、阻挡、治疗最高值 | 帮助发现差异，减少逐格心算 | 趋势给出同口径变化；比较强调差值并同时展示样本量 |
| 英雄立绘脸部 | 身份识别可以由图形加速 | 对局列表保留英雄和地图识别线索；装饰不遮挡姓名和数字 |
| 已查玩家重启后可选 | 产品记住重复劳动 | 返回保留页码、筛选和滚动位置；动作完成后给明确反馈 |
| 数字和排版对齐 | 比较是阅读路径，不是把数据塞进盒子 | 相同指标保持稳定列序、单位和数字对齐；不同页复用同一语义 |

## 表现和状态合同

- 主层：当前对象与核心数据；次层：比较范围、筛选条件；末层：来源、时间、技术详情。
- 对局己方蓝、对方红为展示约定，不声称为上游实际出生阵营。伤害红、阻挡蓝、治疗绿；最高值有文字标注。
- 最高值只比较同队已提供的有限数值；正数并列全部标注；全零、全缺失不授予最高标记。部分数据只能解释为已提供数值中的最高值。
- 页面明确区分加载、失败、无记录与部分缺失；失败可以重试和返回，迟到响应不覆盖新页面。
- 图片是识别线索；没有图片仍可读姓名、英雄与统计。对局卡优先使用本地随应用提供的英雄肖像目录，接口字段和小图标作为降级来源。
- 宽窗口允许并列比较，空间不足时上下显示队伍，不能压缩或截断核心数字来维持并排。
- 后续新页面验收同样检查：第一眼看到什么、比较需要多少次视线往返、返回是否丢上下文、缺失数据是否被误解、键盘是否可用。

## 后续应用范围

生涯以常用英雄和同模式样本为中心；趋势使用一致时间和赛季口径；导出说明范围、完整性和用户名/英雄映射；设置面向连接状态和可执行的恢复操作。每次只强调真正有意义的差异，不能把所有数值都染色。
